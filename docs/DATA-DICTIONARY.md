# 积分规则

会员号、事件号和消费引用均为字符串，前导零保留。积分必须正整数，使用Decimal校验后转为整数，不支持小数积分。事件时刻有时区偏移，统一UTC。规则有效窗与积分可用期均为半开区间。
同一时刻先发放，再消费，最后退款；同类按事件编号排序。消费批次按最早到期、最早发放、批次编号依次选择，余额不足时整笔失败。批次在到期时刻立即不可用，不能消费未来发放积分。
退款必须引用同一会员已成功消费，累计退款不得超过原消费。部分退款按原分配的逆序回拨，先回拨最后消耗的批次；未到期恢复，已到期只记过期退款，绝不复活。后续消费使用回拨后的可用余额。
发放积分=可用积分+已消费积分−全部已退款积分+自然到期积分+过期退款积分。已退款包括有效恢复与过期不恢复。失败消费与失败退款均不改余额，移入隔离。
期末时点默认2026-11-03T00:00:00+08:00，未来事件隔离。示例会员00001：100+80发放，消费120，退款30，其中20恢复、10过期；再消费50后剩余30。

## 来源

`legacy`（旧门店）只提供积分、时间与原单号。`new`（新门店）额外提供兑换渠道与退货原因。

- 输入统一九列：`id,member,type,points,at,expires,ref,rule,version`。可选追加 `source,channel,reason` 三列，列顺序不限。
- 没有 `source` 列的旧文件整批按 `legacy` 采信；带 `channel`/`reason` 列的合并文件默认按 `new` 采信，行内 `source` 可逐行覆盖。
- 旧记录补齐 `source=legacy`、`legacy_compat=true`，不补造渠道与原因，也不因缺列被隔离。
- 同一来源内编号必须唯一。两路来源重复投递同一业务事件（编号、会员、类型、积分、时刻、原单号全部一致）只记一次，优先保留新门店记录，被合并的旧行进入隔离并以 `CROSS_SOURCE_DUPLICATE` 留证。
- 退款只在同来源内按原单号找回原消费；跨来源仅在全局唯一且同会员时兜底。

## 新门店退货依据

每笔 `new` 退货必须同时满足：受控兑换渠道、受控退货原因、可解析的同会员原消费。原消费同为新门店时，原消费渠道也必须可读。缺失或越界只阻断发布，不改变记账算术；被记账阶段隔离的新门店退货仍进入依据清单，以 `QUARANTINED:<原因码>` 标记。

## 发布

对账闸门包含行守恒、积分守恒、退货回拨算术、新门店退货依据四项，全部通过才允许发布。发布在单个事务内完成：旧版本先退位，新版本后生效；中断即回滚，旧版保持 active。同一批次重跑重发复用同一发布号，不产生第二条记录。同日不同批次发布形成递增的发布版本，旧版标记 `superseded`。
